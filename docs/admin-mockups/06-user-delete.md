# 06. Удаление пользователя

Обязательный контекст: [общий контракт](README.md). Один диалог; его допустимость зависит от связей записи. Это удаление учётной записи, не удаление созданных человеком ВСЭ.

## Правило этапа

Владелец запросил возможность удаления, но окончательное правило хранения и удаления данных ещё не определено. Для макета реализовать явное предложение: запись без связанных рабочих документов можно удалить; при наличии связей — запрет удаления и блокировка как альтернатива. Не делать физическое удаление рабочих документов или истории. Правило пометить как проектное в документации адаптера, не как юридическое требование.

## Состав

Диалог из списка/карточки. Фамилия/имя, логин, статус, результат проверки связанных документов. На открытии асинхронная проверка связей с отдельным состоянием ожидания; отсутствие ответа не равно отсутствию связей.

| Состояние | Текст и действия |
| --- | --- |
| Проверка | «Проверяем связанные документы…», «Отмена»; подтверждение недоступно |
| Связей нет | «Удалить пользователя?»; «Учётная запись будет удалена, вход станет недоступен. Отменить удаление в интерфейсе нельзя. История административных изменений сохранится.»; «Отмена», «Удалить пользователя» |
| Есть связи | «Пользователя нельзя удалить»; «У пользователя есть связанные рабочие документы. Заблокируйте учётную запись, чтобы закрыть доступ и сохранить авторство.»; «Закрыть», «Заблокировать» |
| Проверка не удалась | «Не удалось проверить связанные документы»; «Повторить проверку», «Отмена»; удаления нет |

Не требовать ввод имени или слова «УДАЛИТЬ»: идентификации объекта и явного подтверждения достаточно. SVG `admin-delete` общий, опасная кнопка — общий документированный вариант. Фокус изначально на безопасном действии.

## Поведение

- Подтверждение повторно проверяет принадлежность лаборатории, тип учётной записи, версию и связи. Если за время открытого диалога появился документ, ответ запрещает удаление и переводит в состояние связей. Удаление атомарно, без частичного стирания.
- Повторное нажатие заблокировано, подпись «Удаляем…». До успеха строка остаётся. При сетевом отказе диалог остаётся и допускает проверенный повтор; неопределённый результат сначала сверяется адаптером.
- После успеха убрать строку, обновить счётчик/страницу, показать «Пользователь удалён». Из карточки вернуться в сохранённый список. Фокус — следующая строка либо поиск, если строк не осталось.
- Зафиксировать одно событие истории с прежним ID/именем. Оно доступно в демонстрационной истории удалённого пользователя только для чтения, без восстановления или редактирования.
- «Заблокировать» закрывает этот диалог и открывает [05](05-user-block.md), без вложенных модальных слоёв. Для уже заблокированного со связями — сообщение «Пользователь уже заблокирован», без повторной блокировки.
- Отмена и Escape до запроса ничего не меняют. Удаление административного/чужого ID запрещено, даже если вручную вызвать адаптер. Удалённая учётная запись не активируется по старому приглашению.

## Storybook и приёмка

Проверка связей, связей нет, есть связи, заблокирован со связями, ошибка проверки, удаление, ошибка операции, новый документ при подтверждении, длинные сведения и 390 px.

Проверить удаление пользователя без документов, отказ со связанными ВСЭ, гонку появления документа, корректную страницу после удаления последней строки, отсутствие повторного запроса и сохранение авторства/истории. Undo и восстановление не показывать: они не предусмотрены этой моделью.
