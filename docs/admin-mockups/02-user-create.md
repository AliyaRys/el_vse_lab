# 02. Создание пользователя

Обязательный контекст: [общий контракт](README.md). Настройка доступа реализуется тем же блоком [04](04-access-editor.md), который используется в редактировании; не создавать вторую реализацию.

## Назначение и маршрут

`admin-user-create.html`, вход из списка по «Создать пользователя». Общая административная шапка из [01](01-users-list.md). Заголовок «Создание пользователя», ссылка «К списку пользователей». Создаётся только обычный пользователь своей лаборатории; выбора роли, административных полномочий и лаборатории нет.

## Форма

| Поле | Правило |
| --- | --- |
| Фамилия и имя | Обязательное текстовое поле. Не навязывать число слов, кириллицу или отчество |
| Логин | Обязательное текстовое поле, допускается не-email. Уникальность проверяет адаптер |
| Пароль пользователя | Обязательное поле пароля с повтором. Требования — демонстрационная политика из одной конфигурации demo-адаптера, совпадающая с проверкой. Администратор задаёт пароль сам; пользователь входит по логину и паролю |
| Email | Обязательное поле email. Служит контактом для связи, вход по нему не выполняется |
| Должность | Необязательное текстовое поле |
| Лаборатория | Неизменяемое информационное поле из административной сессии |

После основных сведений — единый блок прав и продукции [04](04-access-editor.md). Не использовать загрузку фото, дату регистрации как вводимое поле, индикатор силы пароля, административные полномочия или переключатель «Администратор».

Форма и блоки естественной высоты, читаемые заголовки; действия в конце: «Создать пользователя» и «Отмена». При длинном содержимом нижние действия достижимы обычной прокруткой. Рабочие поля/кнопки имеют плотность приложения, не авторизации.

## Сценарии

1. При первом открытии поля пусты, пять прав выключены, ни один тип продукции не выбран. Лаборатория заполнена. Ничего не наследуется от администратора или предыдущего создаваемого пользователя.
2. При отправке проверить обязательность, пробельные значения, email и пароль: соответствие демонстрационной политике и совпадение повтора. Для имени/логина убрать крайние пробелы. Технические пределы хранить общей конфигурацией.
3. Дубликат логина или email в demo-наборе показывает ошибку у конкретного поля. Политику уникальности для будущего сервера см. README; UI не утверждает, что поиск по таблице — проверка уникальности.
4. Можно создать пользователя без прав и/или продукции. Перед отправкой остаётся видимым предупреждение из блока 04, без модального подтверждения. Это не блокировка учётной записи.
5. После проверки — «Создаём…», одна операция создания. Созданная запись сразу «Активен»; активация и приглашение по email не предусмотрены. Фиксируется одна запись истории.
6. После успешного создания перейти в [карточку](03-user-edit.md) с сообщением «Пользователь создан». Логин и пароль для входа администратор передаёт пользователю вне этой формы.
7. Ошибка создания до появления записи оставляет заполненную форму.
8. При неопределённом исходе запроса адаптер сверяет результат по ID операции перед повтором; двойной клик, Enter и таймаут не создают несколько записей. Не повторять мутацию автоматически.
9. «Отмена»/ссылка/смена маршрута при изменениях используют общий диалог несохранённых изменений. Если ничего не менялось, сразу вернуться в список с его прежним состоянием.

## Компоненты и Storybook

Переиспользовать рабочую кнопку, информационное поле лаборатории, общую шапку и блок 04. Рабочее редактируемое поле/общую форму создать только после проверки существующего API: `InfoField` редактировать не умеет. Для новых общих полей описать label, hint, error, disabled, busy и фокус, использовать их же в 03. SVG — только по общему контракту.

Stories: пустая форма, заполнена, без продукции, без прав, ошибки обязательных полей и пароля, логин занят, email занят, создание, ошибка создания, длинные данные, уход с изменениями, узкий экран. Все ошибки воспроизводимы через адаптер, без специальных слов в продуктовом поле.

## Приёмка

1. Заполненная форма создаёт одну активную запись; выбранные права/продукция совпадают в карточке, списке и истории.
2. Пользователь входит по логину и паролю, заданным администратором; активация и приглашения по email отсутствуют.
3. Ошибка формы и сетевой отказ сохраняют введённое, фокус на первой ошибке; повторная отправка не дублируется.
4. Нет роли, выбора другой лаборатории, прав по умолчанию и индикатора силы пароля. Набор из шести типов не ограничен существующими мясным и молочным маршрутами.
