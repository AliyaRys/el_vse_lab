# 01. Управление пользователями — список

Обязательный контекст: [общий контракт](README.md), особенно правила продукта, владельцы компонентов, SVG и приёмка. Один макет с состояниями; существующие рабочие экраны не копировать.

## Назначение и вход

Администратор находит обычного пользователя своей лаборатории и начинает создание, редактирование или изменение статуса. Маршрут: `admin-users.html`; это старт после входа администратора и адрес логотипа в его шапке. Обычному пользователю прямой переход запрещён до загрузки списка, см. [09](09-access-denied.md).

## Шапка и собственный профиль администратора

- Использовать `VseAppHeader`, расширив его общую конфигурацию административным режимом. Параметр режима, ключ активного пункта и контекст сессии — новая документируемая API; сейчас их нет. Учесть `mountPage` и `app-shell.js`, чтобы они не заменяли административную конфигурацию рабочей.
- В основной навигации только «Управление пользователями» с общей иконкой `admin-users`. Нет «Поступлений», «Журнала ВСЭ», «Справочников» и переключателя продукции. Профиль и «Выйти» остаются на своих местах; учреждение и текущий администратор берутся из сессии, а не из открытой карточки другого человека.
- В профиле администратора переиспользовать `VseProfile.createScreen` через документированное расширение: собственные сведения и смена собственного пароля доступны; рабочие права и продукция не изображаются назначенными. Вместо рабочих разрешений — неизменяемое «Управление пользователями». Это технический административный контекст, не шестой флажок прав. Редактора собственных прав нет.
- В рабочей конфигурации шапки нового пункта нет. Существующие иконки и интервалы не меняются. Проверки маршрутов обязательны независимо от видимости пункта.

## Состав

Заголовок «Управление пользователями», название лаборатории, основное действие «Создать пользователя». Под ним одна строка управления: поиск «ФИО, логин или email», фильтры «Статус» и «Тип продукции», «Сбросить фильтры» при активном ограничении.

| Столбец | Содержимое |
| --- | --- |
| Пользователь | Фамилия и имя — ссылка на карточку; логин второй строкой |
| Продукция | Число назначенных типов или «Не назначена»; полный перечень в карточке |
| Статус | «Активен», «Заблокирован» текстом |
| Дата создания | Дата/время |
| Действия | Редактирование, меню дополнительных действий |

Без столбца «Роль», широкого перечня пяти флажков в строке и повторяющегося названия лаборатории. Семантическая таблица на широком экране; на 390 px допустим компактный список с теми же данными/действиями. Длинное имя раскрывается в карточке, не только подсказкой по hover.

## Поведение

- Локальный поиск действует сразу, без учёта регистра, по имени, логину и email. Фильтры совмещаются через «И», сбрасывают страницу на первую. Фильтр продукции включает все шесть точных типов из [04](04-access-editor.md). Отдельного права на просмотр не вводить.
- Непустой поиск имеет кнопку очистки с именем «Очистить поиск» и возвратом фокуса. При будущем удалённом поиске — debounce 300 мс, отмена/игнорирование устаревших ответов.
- Сортировка: «Сначала новые» по умолчанию и «По имени А–Я»; одинаковые даты/имена стабилизируются ID. Пагинация по 20 записей, счётчик «Показано 1–20 из 43», границы отключены. Фикстура не менее 25 пользователей для реальной проверки страниц.
- Переход в карточку и возврат восстанавливают поиск, фильтры, сортировку, страницу и позицию. После удаления последней строки страницы перейти на предыдущую валидную. Если сохранённый пользователь не проходит фильтр, показать сообщение и ссылку на его карточку, не сбрасывать фильтры молча.
- «Редактировать» открывает [03](03-user-edit.md). Дополнительные действия: история [08](08-user-history.md), блокировка/разблокировка [05](05-user-block.md), удаление [06](06-user-delete.md). Набор определяется состоянием; активации и повторного приглашения нет ([07](07-account-activation.md)).
- Меню открывается кнопкой с доступным именем конкретного пользователя, закрывается Escape/нажатием вне, возвращает фокус. Не помещать активные кнопки внутрь ссылки всей строки.
- Собственная административная запись и другие администраторы не являются редактируемыми строками списка обычных пользователей. Подстановка их ID не открывает форму изменения.

## Состояния и Storybook

Шапка: администратор / длинное учреждение и имя / узкий экран / собственный профиль. Список: заполнен, первоначальная загрузка, ошибка с «Повторить», пользователей ещё нет, поиск без совпадений с «Сбросить фильтры», вторая страница, длинные данные, меню открыто, успех действия, 390 px. Пустая лаборатория предлагает «Создать пользователя»; отсутствие совпадений не предлагает создать дубликат.

## Приёмка

1. Вход администратора и логотип ведут в список; рабочая навигация отсутствует, профиль и выход работают.
2. Две страницы данных, комбинированный фильтр, очистка и возврат из карточки работают, количество соответствует выдаче.
3. Администратор не видит чужую лабораторию и не редактирует себя даже через ID.
4. Шапка создана общим компонентом; контроль геометрии и неизменности SVG рабочего режима проходит по README. Все пункты меню запускают описанный сценарий.
