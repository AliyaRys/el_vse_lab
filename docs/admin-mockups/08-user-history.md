# 08. История изменений пользователя

Обязательный контекст: [общий контракт](README.md). Один экран только для чтения, не общесистемный журнал безопасности.

## Назначение и маршрут

Администратор проверяет, кто и когда менял данные, доступ и статус конкретного обычного пользователя своей лаборатории. `admin-user-history.html?user=<id>`, переход из карточки или меню строки списка. Общая административная шапка; «К карточке пользователя» и «К списку пользователей» с сохранённым контекстом списка.

## Композиция

Заголовок «История изменений», сводка фамилия/имя и логин. Текст «Время указано по Москве (МСК)». Фильтр «Событие»: все, создание, данные пользователя, права, продукция, статус, удаление. Активации и приглашений больше нет ([07](07-account-activation.md)). Допускаются нативные списки, как в существующих макетах; не вводить новый сложный select только ради фильтра.

Список по убыванию времени, одинаковое время стабилизируется ID события. По 20 событий на страницу, подпись диапазона и рабочие кнопки страниц. Для каждого события дата/время, исполнитель, действие и детали; на узком экране эти сведения идут вертикально. Нет редактирования, удаления или «отката» истории.

## Детали событий

| Событие | Что видно |
| --- | --- |
| Создание | Кто создал; исходные пять прав и продукция |
| Изменение данных | Только изменённые поля, прежнее и новое значения |
| Права/продукция | «Добавлено» и «Отозвано» полными русскими подписями; не JSON и не одни числа |
| Блокировка/разблокировка | Прежний и новый статусы; исполнитель |
| Удаление | Кто удалил, время, прежний ID и отображаемое имя; без восстановления |

Для пустого набора явно «Не назначено». Одно сохранение с несколькими изменениями — одно составное событие, детали сгруппированы. Отмена формы/диалога и неуспешное изменение не выдаются за успешное изменение прав.

## Поведение и ограничения

- Фильтр сбрасывает страницу, очистка возвращает все события; выход в карточку и обратно сохраняет фильтр/страницу на время сессии.
- Обновление не создаёт события. Возврат адаптера после фактической операции добавляет событие один раз. Данные истории и карточки связаны стабильным ID, а не только именем/логином.
- История удалённой записи доступна по её известному адресу в демо и отображается с отметкой «Пользователь удалён». Ссылка на редактирование отсутствует, «К списку пользователей» доступна. В будущем срок хранения/доступность определяются отдельной политикой, не этим макетом.
- Чужая лаборатория, обычный пользователь или административный объект не открывают историю через прямой URL. До отказа не выводить сводку личности или события.
- Длинные перечни можно раскрывать «Показать изменения» без нового маршрута: кнопка с `aria-expanded`, доступ к полной подписи без hover, фокус остаётся на кнопке.

## Компоненты, Storybook, приёмка

Использовать общую шапку, информационные поля и общий справочник доступа из 04. Иконка истории `admin-history` из реестра, без нового SVG на странице. Для повторяющейся строки истории — общий компонент, если она используется в других представлениях.

Stories: несколько событий, пустая история, фильтр без результатов, загрузка, ошибка с повтором, составное изменение всех шести типов, удалённый пользователь, длинные данные, 390 px.

Проверить соответствие события фактическому сохранению, отсутствие событий при отмене/дублирующем клике, полный diff пяти прав/шести типов, фильтр и вторую страницу, отсутствие пароля/токена и сохранение истории после демонстрационного удаления.
