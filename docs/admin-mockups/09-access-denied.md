# 09. Нет доступа / доступ отозван

Обязательный контекст: [общий контракт](README.md). Один общий экран состояния с разными причинами, без переработки всех рабочих экранов.

## Назначение

Показать понятный отказ при прямом открытии запрещённого маршрута или при отзыве необходимого права/типа продукции во время работы. Предлагаемый маршрут `access-denied.html`; причина задаётся допустимым кодом состояния, не произвольным текстом URL и не персональными сведениями.

## Композиция

Действующая общая шапка текущей учётной записи: рабочая для специалиста, административная для администратора. Доступные ссылки, профиль и выход остаются работоспособны. В центре обычной рабочей области компактный блок сообщения, без новой иллюстрации и без замены логотипа. Цвет не единственный признак состояния.

| Причина | Заголовок и текст | Действия |
| --- | --- | --- |
| Нет права/доступа к разделу | «Нет доступа»; «У вас нет доступа к этому разделу. Обратитесь к администратору лаборатории.» | «Перейти в доступный раздел», «Открыть профиль» |
| У пользователя забрали доступ во время заполнения | «Доступ изменён»; «Администратор изменил ваш доступ. Несохранённые изменения не сохранены.» | Переход в оставшийся доступный раздел; профиль |
| Недоступный тип продукции | «Нет доступа к этому типу продукции»; без реквизитов чужой партии | «Выбрать доступную продукцию», если выбор ещё есть; иначе переход в 11 |
| Администратор открыл рабочую страницу | «Этот раздел недоступен для административной учётной записи» | «К управлению пользователями» |

Если отозвано только право действия, а чтение этого объекта остаётся разрешено, экран может предложить «Открыть сохранённую версию». Эта ссылка ведёт в существующий просмотр без новых правок. Если отозвана продукция/лабораторный доступ, её нет.

## Отзыв доступа во время работы — обязательный сценарий

1. Рабочая форма проверяет актуальные право действия, тип продукции, лабораторию и статус при открытии и перед сохранением. В демо изменение доступа поступает через общий store/подписку; на возвращении во вкладку состояние перепроверяется.
2. На обнаружение отзыва необходимого права или продукции немедленно прекратить редактирование. Пока проверка не завершена, сохранение недоступно. Не отображать запрещённое содержимое в фоне нового экрана.
3. **Не сохранять несохранённую запись и изменения.** Отменить локальное автосохранение/отложенную отправку, убрать соответствующий несохранённый draft из памяти/локального demo-хранилища. Существующие сохранённые версии и документы не удалять.
4. Не предлагать «Сохранить черновик», «Скопировать данные», «Экспортировать», «Войти и продолжить» или восстановление запрещённых данных после выдачи доступа заново. Диалог несохранённых изменений здесь не препятствует отзыву.
5. Если сохранение и отзыв пересеклись, решает атомарная проверка адаптера, впоследствии сервера. При отказе мутация не применяется, статус успеха не появляется. Если сервер успел законно сохранить до отзыва, не заявлять, что эта уже сохранённая версия удалена; состояние разрешать по подтверждённому результату.
6. Не сбрасывать чужие или ранее сохранённые черновики глобально: отбрасываются только текущие несохранённые изменения, утратившие разрешение. Отзыв права удаления не должен уничтожать форму, которая требует только `vse_write`.
7. «Назад», обновление, старый deep link и старый `vse-product-type` не обходят проверку. Нельзя вернуть запрещённую форму кнопкой браузера вместе с редактируемыми данными.

Если закончился сеанс без изменения доступа, это отдельная причина: предложить повторный вход, не заявляя об отзыве. Если учётная запись заблокирована — переход в [10](10-account-blocked.md); если активна и продукции нет — [11](11-no-products.md). Причины не смешивать в одном неопределённом сообщении.

## Навигация и состояние шапки

«Доступный раздел» вычисляется из актуальной сессии. Для администратора это список пользователей. Для обычного пользователя — разрешённый реализованный рабочий маршрут, при отсутствии продукции — 11. Для назначенного, но ещё не реализованного направления — честное «Раздел ещё не реализован», без перенаправления в мясо/молоко. Нет ссылки «Назад», которая циклически возвращает на запрещённый адрес.

Шапка со списком разрешённой продукции — расширение общего `AppHeader`; не удалять варианты локальным DOM/CSS. Вариант без продукции принадлежит тому же компоненту. Набор действий на существующих экранах вычислять общей моделью доступа по пяти точным флагам; не вводить локальные массивы «ролей» и не заменять SVG.

## Storybook и приёмка

Состояния всех причин, остаётся доступное чтение, отозвана продукция, нет оставшейся продукции, загрузка проверки, отказ проверки сети без раскрытия данных, узкий экран. Техническое переключение доступа — только Controls/фикстура, не пользовательская кнопка «Отнять себе права».

Браузерный тест: пользователь с `vse_write` открывает форму сырого молока → вводит изменение → администратор снимает `vse_write` → форма прекращает редактирование → сохранения и несохранённого draft нет, прежняя запись цела. Повторить с отзывом продукции, сохранением одновременно с отзывом и возвратом назад. Контрольный тест: снятие неиспользуемого `vse_delete` не мешает разрешённому сохранению.
