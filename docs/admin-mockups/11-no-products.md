# 11. Типы продукции не назначены

Обязательный контекст: [общий контракт](README.md). Один экран состояния для **активного обычного пользователя** без назначенных типов продукции. Администратора сюда не направлять: отсутствие рабочих типов у него нормально.

## Вход и назначение

Предлагаемый маршрут `no-products.html`. Показывать после успешного входа, при открытии рабочего маршрута без доступной продукции или после отзыва последнего типа. Пользователь может войти, открыть собственный профиль и выйти, но не увидеть рабочие записи. Наличие любого из пяти прав не заменяет доступ к продукции.

## Композиция

Использовать обычный фон и ширину рабочей области, общую шапку, спокойный блок с заголовком **«Типы продукции не назначены»**. Текст: «Для работы с поступлениями, журналом ВСЭ и справочниками администратор должен назначить вам доступные типы продукции. Обратитесь к администратору вашей лаборатории.»

Действия: «Открыть профиль» и «Проверить доступ». Выход остаётся в шапке. Нет кнопок «Назначить себе», «Создать ВСЭ» или «Выбрать мясо»; пользователь сам доступа не выдаёт. Не показывать фиктивный контакт администратора или форму обращения.

## Шапка и профиль

- Это документированный вариант общего `AppHeader`, не отдельная облегчённая копия. Бренд, учреждение, профиль и выход сохраняют геометрию и действующие SVG.
- Рабочие разделы без допустимого адреса не являются активными ссылками в пустые мясные/молочные данные. Состав навигации вычисляет общий компонент; в этом состоянии рабочие ссылки и переключатель продукции не выводятся. Не рисовать выбранный первый тип и не брать его из localStorage.
- Собственный профиль использует общий `VseProfile` с явными данными: «Типы продукции не назначены», пять реально назначенных прав либо «Дополнительные права не назначены». Нет старых дефолтных типов. Из профиля есть рабочий путь обратно к этому состоянию и выход.
- Пустая продукция и пустые права — разные случаи. Если продукция назначена, но пять дополнительных прав выключены, этот экран не показывать: разрешённое базовое чтение остаётся по проектному решению README.

## Проверка доступа

1. «Проверить доступ» перечитывает текущую сессию/назначения через адаптер. Кнопка «Проверяем…» блокирует повторы. При отсутствии изменений — «Доступные типы продукции пока не назначены», без ложного успеха.
2. При ошибке — «Не удалось проверить доступ. Попробуйте ещё раз», старое безопасное состояние остаётся, повтор доступен. Сетевой отказ не означает, что доступ предоставлен.
3. Если администратор назначил тип, обновить модель и общую шапку. При одном реализованном типе — переход в его разрешённый рабочий раздел; при нескольких — выбор через общий переключатель. Коды и связь маршрутов определяет адаптер из 04, не условие «всё кроме мяса — молоко».
4. Если назначены только направления без готовых макетов, показать в той же рабочей композиции сообщение «Доступ назначен. Раздел для выбранного типа продукции ещё не реализован» с полным названием. Профиль/выход и выбор других назначенных типов остаются доступны. Не создавать четыре пустых псевдожурнала и не менять назначение пользователя.
5. Если пользователь заблокирован при проверке — [10](10-account-blocked.md), если сеанс истёк — обычный повторный вход. При отзыве последнего типа во время ввода сначала отбросить текущие несохранённые изменения по [09](09-access-denied.md), затем показать это состояние с пояснением потери изменений.

## Storybook и приёмка

Stories: продукция не назначена, права есть/продукции нет, проверка, без изменений, ошибка/повтор, тип назначен, назначено только неготовое направление, последний тип отозван, длинное учреждение/имя, профиль без продукции, 390 px.

Проверить отсутствие доступа через старый маршрут и `vse-product-type=meat`, действующие профиль/выход, выдачу доступа в другой вкладке с последующей проверкой, переход только в допустимую продукцию, различение пустых прав и пустой продукции. Режим шапки имеет общий runtime и не изменяет размеры/иконки остальных режимов.
