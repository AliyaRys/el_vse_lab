# 10. Учётная запись заблокирована

Обязательный контекст: [общий контракт](README.md). Это состояние существующего `login.html`, а не новая самостоятельная страница входа.

## Назначение

Пользователь понимает, почему не может войти или почему завершилась работа после блокировки администратором. Удаление пользователя, ошибка пароля и отсутствие продукции не должны отображаться как блокировка.

## Макет и переиспользование

Использовать `VseAuth.createLoginScreen` / `createLoginForm` с их реальными API ошибок/статуса. Новые параметры при необходимости добавить в общий компонент и README, без второй формы. Сохранить фон, логотип, поля, геометрию кнопки, ссылки и адаптацию `login.html`. Здесь нет рабочей/административной шапки и списка продукции.

При подтверждённой блокировке показать в форме устойчивое сообщение: **«Учётная запись заблокирована. Обратитесь к администратору лаборатории.»** Сообщение связано с формой, доступно скринридеру и не является кратким исчезающим toast. Не выдумывать email, телефон или кнопку отправки обращения.

## Поведение

- При входе статус блокировки раскрывается только после проверки учётных данных либо при прекращении ранее подтверждённого сеанса. Не показывать блокировку только по введённому существующему логину. Для неизвестной записи/неверного пароля — одинаковый обычный отказ входа.
- После блокировки открытого сеанса прекратить дальнейшие операции, очистить сессионные данные, убрать защищённый контент и перейти во вход с объяснением. Несохранённое не сохраняется по [09](09-access-denied.md); сохранённые записи не удаляются.
- После перенаправления поле пароля пустое. Введённый при новой попытке пароль существует только в памяти формы, не передаётся query-параметром и не журналируется. Изменение поля снимает ошибку формы по существующим правилам, но не разблокирует учётную запись.
- Кнопка входа остаётся доступной для другой учётной записи; не блокировать форму целиком и не создавать бесконечный автоматический повтор. Переход в восстановление пароля работает, но не обещает снять административную блокировку. Сохраняется нейтральное сообщение восстановления для существующего и несуществующего адреса.
- После разблокировки пользователь повторно входит. Ранее открытый сеанс не восстанавливается автоматически и прежняя несохранённая форма не возвращается.

## Storybook

В «Вход / Форма входа» и экране входа: подтверждённая блокировка, завершённый сеанс, неверные данные без раскрытия статуса, ожидание, ошибка соединения, 390 px. Примеры используют фиктивный адаптер, не словарь реальных заблокированных логинов. Не добавлять свободный флаг в URL, который выглядит доказательством реальной блокировки.

## Приёмка

1. Блокировка во второй вкладке прекращает подтверждённый сеанс, пароль и защищённая форма не видны после возврата/обновления.
2. По одному логину нельзя узнать статус блокировки; другая разрешённая учётная запись входит через ту же форму.
3. Восстановление пароля не снимает блокировку; разблокировка не выдаёт новых прав.
4. Внешний вид входа и прежние сценарии не изменены. После обновления auth — `npm.cmd run build-storybook`, затем `npm.cmd run test:ui` и предметные проверки блокировки.
