# 04. Права доступа и доступные типы продукции

Обязательный контекст: [общий контракт](README.md). Это **один встроенный макет-компонент** для создания и редактирования, не отдельный маршрут и не дубликат карточки. Его код находится в `components/admin/`, stories рядом.

## Модель

Два независимых списка флажков: «Права доступа» и «Доступные типы продукции». Права задаются целиком для пользователя и применяются ко всем его назначенным типам. Лаборатория задаётся сессией. Не добавлять роли, обязательный административный доступ, «Полный доступ», предустановки или матрицу по каждому виду продукции.

## Права — точные подписи

| Код для demo-модели | Подпись |
| --- | --- |
| `vse_write` | Создание и редактирование ВСЭ |
| `vse_delete` | Удаление ВСЭ |
| `expected_party_delete` | Удаление ожидаемых партий |
| `directory_edit` | Редактирование справочников |
| `directory_delete` | Удаление справочников |

Все пять переключаются независимо. «Создание и редактирование ВСЭ» — один флажок. Удаление не включает редактирование и наоборот. Не добавлять «Просмотр ВСЭ» или «Создание справочников» из старых демонстрационных данных профиля.

Под списком: «Права действуют для назначенных типов продукции в вашей лаборатории». Для пустого набора: «Дополнительные права не назначены. Просмотр доступной продукции сохраняется». Базовое чтение — проектное решение из README, не шестое разрешение.

## Продукция — точные подписи и порядок

| Код для demo-модели | Подпись |
| --- | --- |
| `meat` | Мясо и продукты убоя животных |
| `raw_milk` | Сырое молоко, сырые сливки, сырое обезжиренное молоко, сырые сливочные и молочные продукты |
| `eggs` | Яйца сельскохозяйственных птиц, яйцепродукция |
| `fish` | Рыба, водные беспозвоночные, рыбная продукция |
| `bee_products` | Мёд, перга и молочко маточное пчелиное |
| `plant_food` | Растительная пищевая продукция |

Не сокращать наименования до «Мясо», «Молоко» и не заменять сырые молочные продукты всеми молочными продуктами. В админской форме, профиле и деталях истории полные названия видимы с переносом; не в tooltip и не только в раскрывающемся меню. В таблице списка допустимо число типов со ссылкой в карточку.

Хранить подписи/коды в одном общем справочнике. `raw_milk` — новый код предметного доступа, а существующий `milk` в шапке — ключ маршрутов/иконки. Связь задать явным адаптером, не переименовывать маршруты и storage-ключи автоматически. Текущие молочные макеты охватывают и переработанную продукцию: соответствие их страниц этому типу требует отдельного решения владельца. Не объявлять все такие страницы разрешёнными только из-за `raw_milk`; в демонстрационных проверках доступа использовать однозначные сценарии сырого молока.

## Взаимодействие

- Нативные checkbox с отдельными `label` и группами `fieldset/legend`; клик по тексту переключает флажок, Space работает. Не реализовывать checkbox дивами и картинками.
- При создании всё выключено; при редактировании точно восстановлены сохранённые значения. Чтение данных не меняет флаги. Флажки не сохраняются сразу: возвращают состояние общей форме, которая сохраняет всё одной операцией.
- Нулевой набор продукции допустим для демо. Непосредственно под списком: «Типы продукции не назначены. Пользователь сможет войти, но не увидит рабочие записи». Если права есть, это же сообщение объясняет, почему они пока не дают рабочего доступа. Не выдавать автоматически первый тип.
- Есть тихая сводка «Прав: 2 из 5 · Типов продукции: 1 из 6». Частичный выбор не выводить как «Полный доступ». Сводка предназначена для контроля, не отдельная карточка статистики.
- При загрузке/отправке флажки недоступны, значения и размеры сохраняются. У чужого/собственного административного ID блок не монтируется как редактор.
- После отзыва доступного типа текущий выбранный тип нельзя восстанавливать из старого `vse-product-type`. Сначала проверять доступный набор; если остались типы, предлагать разрешённый, если нет — [11](11-no-products.md). Не изменять другие типы и права каскадно.
- Право на удаление ожидаемой партии не разрешает удаление партии «В работе»/«Завершённой». `directory_delete` не является разрешением удалить пользователя. Связку проверять по смыслу действия, а не общему слову «Удалить».

## Storybook

Пустой набор, частичный, все права/продукция, только права без продукции, продукция без дополнительных прав, загрузка, недоступный блок, длинная молочная подпись, отзыв выбранного типа, 390 px, клавиатурный фокус. В stories создаются экземпляры того же компонента, который встроен в 02 и 03.

## Приёмка

1. На всех экранах ровно пять прав и шесть типов с указанными подписями; у обычного пользователя нет роли.
2. Выбор/снятие флажка не меняет остальные и не вызывает сохранение; отмена родительской формы возвращает исходное.
3. Одинаковый набор читается карточкой, профилем и историей из общего справочника. Старые права профиля не появляются.
4. На 390 px полное название сырой молочной продукции читается, вся подпись кликабельна, следующий флажок не перекрывается.
5. В тестах отдельно проверены независимые права удаления и редактирования, привязка лаборатории и запрет восстановления отозванной продукции из storage.
