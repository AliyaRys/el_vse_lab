# Управление пользователями

`AdminData.js` хранит единый справочник из шести типов продукции, статусов и синтетическую фикстуру обычных пользователей одной лаборатории. `AdminUsersList.js` создаёт интерактивный список через `VseAdmin.createUsersList(options)`.

`AdminDemoStore.js` — демонстрационный асинхронный адаптер. Он проверяет уникальность логина/email, обеспечивает идемпотентность операции создания по `operationId` и хранит созданные записи в пространстве `vse-admin-demo-v1`. `VseAdminDemo.getUsers()` объединяет базовую фикстуру и созданные записи.

## Формы

- `VseAdmin.createTextField(options)` создаёт редактируемое рабочее поле с подписью, подсказкой, ошибкой, обязательностью и состоянием busy/disabled. Методы экземпляра: `setError(message)`, `setBusy(value)`.
- `VseAdmin.createAccessEditor(options)` создаёт общий блок пяти прав и шести типов продукции. Методы: `getValue()`, `setValue(value)`, `setDisabled(value)`. Флажки не сохраняются самостоятельно.
- `VseAdmin.createUserForm(options)` создаёт форму нового обычного пользователя. Она использует `VseApp.createButton`, `VseApp.createInfoField`, общее поле и редактор доступа. Методы: `isDirty()`, `isSubmitting()`, `getValue()`, `focusFirst()`.
- `VseAdminDemo.createUser(payload, options)` выполняет одну идемпотентную операцию создания, проверяет дубликаты логина/email, применяет демонстрационную политику пароля `VseAuth.demoPasswordPolicy` и создаёт сразу активную запись: логин и пароль задаёт администратор, пользователь входит по ним.
- `VseAdmin.createUserStatusDialog(options)` создаёт общий диалог блокировки и разблокировки. Открывайте его через `dialog.openFor({ user, trigger })`; статус сохраняет `adapter.setUserBlocked`, а `onSuccess(user, detail)` обновляет инициирующий экран только после ответа.
- `VseAdminDemo.setUserBlocked(id, blocked, options)` идемпотентно меняет статус, проверяет `expectedStatus`, сохраняет одно событие истории и при разблокировке возвращает пользователя в `active`. Права и продукция не меняются.
- `VseAdmin.createUserDeleteDialog(options)` создаёт диалог проверки связей и удаления. `openFor({ user, trigger })` сначала вызывает `adapter.checkUserDeletion`; при связях `onRequestBlock` открывает диалог блокировки только после закрытия текущего слоя.
- `VseAdminDemo.checkUserDeletion(id)` и `VseAdminDemo.deleteUser(id, options)` реализуют проектное правило демонстрации: удалить можно обычного пользователя своей лаборатории без связанных рабочих документов. Удалённая запись исключается из активного списка, а её административная история сохраняется в `deletedUsers` и доступна через `getDeletedUser(id)` только для чтения. Это проектное допущение, а не юридическое правило хранения.
- `VseAdmin.createUserHistory(options)` создаёт read only историю одного пользователя с фильтром типов событий, стабильной сортировкой и пагинацией по 20 записей. Методы экземпляра: `setViewState(state)` и `setEvents(events)`; фильтр доступен в `.controls.filter`.
- `VseAdmin.createUserHistoryEvent(event)` создаёт одну строку истории. Составные изменения показывают прежние и новые значения, а длинный перечень раскрывается кнопкой с `aria-expanded`.
- `VseAdminDemo.getUserHistory(id, options)` проверяет область доступа и возвращает пользователя вместе с событиями. Удалённые записи читаются из `deletedUsers`; пароли в события не включаются.

Форма содержит пароль и его повтор, но не содержит роль, выбор лаборатории или административные полномочия; активации и приглашений по email нет. Пустые права и продукция допустимы и сопровождаются предупреждениями редактора доступа.

## API списка

- `users` — массив пользователей; по умолчанию `VseAdmin.createDemoUsers()` (28 записей).
- `initialState` — `ready`, `loading` или `error`.
- `restoreState` — восстанавливает поиск, фильтры, сортировку и страницу из `sessionStorage`; в Storybook отключается.
- `links.card`, `links.edit`, `links.history` — маршруты связанных административных экранов.
- `onRetry` — обработчик повторной загрузки.

Поиск выполняется по ФИО, логину и email без учёта регистра. Фильтры статуса и продукции объединяются через «И». Сортировка стабильна по ID, пагинация показывает по 20 строк. Компонент переключается в карточное представление на узком экране без отдельной бизнес-логики.

Административные иконки создаются только через `VseIcons.create()` и основаны на **Lucide Static 1.60.0**. Лицензия сохранена в `components/icons/LUCIDE-LICENSE.txt`.
