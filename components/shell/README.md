# Шапка системы

`AppHeader.js` — единственный источник разметки, иконок и поведения шапки. HTML-страницы вызывают `VseAppHeader.mountPage()`, а Storybook — `VseAppHeader.create()`. Локальные копии и альтернативные SVG в страницах не добавляются. Рабочий и административный режимы используют одну геометрию бренда, профиля и выхода.

## Каноническая геометрия

| Элемент | Значение |
| --- | --- |
| Высота шапки | 76 px |
| Максимальная ширина рабочей области | 1440 px |
| Минимальный боковой отступ | 24 px |
| Расстояние между брендом, навигацией и профилем | 12 px |
| Логотип | 43 × 43 px |
| Зона бренда | 295 px |
| Расстояние между логотипом и названием | 12 px |
| Смещение навигации после бренда | 8 px |
| Расстояние между пунктами навигации | 6 px |
| Высота пунктов навигации | 42 px |
| Радиус пунктов навигации | 10 px |
| Горизонтальный отступ внутри пункта | 12 px |
| Расстояние между иконкой и текстом | 9 px |
| Навигационная иконка | 19 × 19 px |
| Переключатель продукции | 310 × 42 px |
| Иконка продукции | 20 × 20 px |
| Стрелка переключателя | 14 × 14 px |
| Аватар | 32 × 32 px |
| Расстояние в блоке пользователя | 5 px |

На ширине до 1240 px скрывается текст бренда, но логотип сохраняет слот 43 px. До 1200 px скрывается имя пользователя. До 920 px пункты основной навигации переходят к иконкам. На ширине до 800 px включается компактная мобильная геометрия без изменения высоты шапки.

## Иконки и их назначение

| Назначение | Ключ |
| --- | --- |
| Поступления | `arrivals` — контур посылки |
| Журнал ВСЭ | `journal-classic` — прямоугольный журнал с разделителем и строками, визуально близкий к `▦` |
| Справочники | `directories-classic` — классическая симметричная шестерёнка |
| Мясо и продукты убоя | `meat` |
| Молоко и молочная продукция | `milk` |
| Раскрытие списка продукции | `caret` |
| Управление пользователями | `admin-users` из общего `VseIcons` |

Иконка выбирается по назначению пункта и не меняется между страницами или типами продукции. Все SVG создаются функцией `VseAppHeader.createIcon(name)`.

## API

- `VseAppHeader.create(options)` создаёт шапку и возвращает `<header>` с методами `setProduct(product)` и `setMenuOpen(open)`.
- `options.mode` принимает `work` (по умолчанию), `admin` или `no-products`. В режиме `admin` показывается только пункт «Управление пользователями», рабочая навигация и переключатель продукции отсутствуют. Для активного пункта используется `active: 'users'`. В режиме `no-products` (экран «Типы продукции не назначены») рабочие ссылки и переключатель продукции не выводятся совсем: остаются бренд, учреждение, профиль и выход; пустая навигация скрывается.
- `options.links.adminUsers`, `links.brand` и `links.profile` задают административные маршруты. Учреждение, имя и инициалы администратора передаются через те же `institution`, `userName`, `userInitials`, что и в рабочем режиме.
- `VseAppHeader.mountPage(document)` заменяет существующую `.topbar` канонической шапкой, сохраняя активный раздел, тип продукции, учреждение и пользователя.
- Для административной страницы placeholder `.topbar` получает `data-app-header-mode="admin"`; маршруты можно передать через `data-brand-href`, `data-admin-users-href`, `data-profile-href`, а путь к логотипу вложенной страницы — через `data-logo-src`.
- `VseAppHeader.spec` содержит утверждённые размеры для документации и автоматических проверок.

## Экран отказа в доступе

`AccessDenied.js` добавляет `VseAppHeader.createAccessDenied(options)` — общий компактный блок состояния поверх обычной рабочей области; шапку страницы создаёт вызывающий код в режиме `work` или `admin`. Причина задаётся только кодом: `no-permission`, `changed`, `product-denied`, `admin-page`; произвольный текст причины из URL не принимается. Опции: `checkState` (`checking`, `network-error` — проверка доступа и отказ сети без раскрытия данных), `hasAvailableProducts`, `savedView` (ссылка «Открыть сохранённую версию» — только когда чтение объекта разрешено), `links` (`available`, `profile`, `products`, `adminUsers`, `saved`) и `onRetryCheck`. Ссылка «Перейти в доступный раздел» вычисляется из сессии вызывающим кодом; сам экран не угадывает маршруты. Стили — `access-denied.css`, область ограничена `.vse-access-denied`.

## Типы продукции не назначены

`NoProducts.js` добавляет `VseAppHeader.createNoProducts(options)` — экран состояния активного обычного пользователя без назначенных типов продукции (маршрут макета `no-products.html`). Шапка создаётся вызывающим кодом в режиме `no-products`. Опции: `state` (`idle`, `checking`, `unchanged`, `network-error`, `assigned`, `unimplemented`, `revoked`), `permissions` — массив реально назначенных прав для пояснения, что они не заменяют доступ к продукции, `unimplementedLabel` — полное название неготового направления, `links.profile` и `onCheck`. Обработчик проверки может вернуть `{}` (без изменений), `{ error: true }` (сетевой отказ, безопасное состояние остаётся) или `{ message }` (например, о назначении типа — модель и шапку обновляет вызывающий код). Кнопка проверки блокирует повторы и показывает «Проверяем…». Дополнительные стили — `no-products.css`, композиция карточки общая с `access-denied.css`.
