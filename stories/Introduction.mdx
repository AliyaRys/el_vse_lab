# Библиотека компонентов лаборатории ВСЭ

Компоненты выделены из макетов **login**, **password-recovery**, **profile** и четырёх экранов сверки данных. Каталог и реальные страницы используют один и тот же код.

## Что посмотреть сначала

Откройте в левом меню **Вход → Экран входа → Полный экран**. Затем посмотрите отдельные элементы в согласованном порядке:

1. **Поле ввода** — обычное, email, пароль, ошибка, недоступное, с пояснением, длинной подписью и в фокусе.
2. **Кнопка** — вход, восстановление, ожидание, недоступное состояние, длинная подпись и фокус.
3. **Ссылка** — восстановление пароля, вариант возврата, длинная подпись и фокус.
4. **Форма входа** — композиция общих компонентов с ошибками и ожиданием.
5. **Экран входа** — всё вместе, в том числе на узком экране.
6. **Восстановление пароля** — форма, ожидание и подтверждение отправки с адресом или без него.
7. **Сверка данных → Компоненты** — минимальные элементы сравнения, состава партии, перевозки и исследований.
8. **Сверка данных → Блоки** — секция сверки, ранее проведённая ВСЭ и расчёт стоимости, собранные из компонентов выше.
9. **Профиль** — кнопка, информационное поле, карточка пользователя, смена пароля и собранный экран.

## Как проверить компонент

Выберите пример в левом меню. В панели **Controls** можно менять доступные параметры: подпись, ошибку, недоступность и другие настройки. Страница **Docs** у каждого компонента содержит его описание и варианты.

Наведите мышь на элемент, чтобы проверить наведение. Нажмите Tab, чтобы проверить клавиатурный фокус. Отдельные примеры «В фокусе» включают его автоматически.

Для просмотра телефона используйте пример «Узкий экран» или инструмент выбора размера в верхней панели. Чтобы вернуться к ширине окна, выберите адаптивный размер.

## Проверка формы

В обычной форме нажмите «Войти» с пустыми полями: появятся ошибки и фокус на первом поле. Затем введите фиктивные данные и отправьте форму снова.

**В Storybook всё демонстрационное:** ожидание и отказ имитируются, переходы не выполняются, настоящая авторизация не подключена. В самом `login.html` сохранён демонстрационный переход на страницу журнала.

## Как библиотека связана с макетом

Общий код находится в `components/auth/`, `components/app/`, `components/profile/` и `components/checks/`. HTML подключает обычные скрипты, а Storybook импортирует те же файлы. Изменение общего компонента влияет на оба представления.

Макеты `evsd-check-usmanov.html`, `evsd-check-agro.html`, `evsd-check-milk-ak-bars.html` и `evsd-check-milk-nur.html` подключены к общему слою сверки. Следующие экраны нужно переводить на библиотеку постепенно: сначала повторно использовать готовые элементы и добавлять только отсутствующие составные части.

## Как открыть каталог снова

Попросите Codex: «Запусти Storybook и открой экран входа».

Или выполните в PowerShell:

```powershell
cd C:\journal
npm.cmd run storybook
```

Оставьте терминал открытым и перейдите на `http://localhost:6006`.

Подробная инструкция — `STORYBOOK.md`; API компонентов — `components/auth/README.md` и `components/checks/README.md`; правила оформления — `DESIGN.md`, поведение — `UX-CONTRACT.md`.
