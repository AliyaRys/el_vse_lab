# Библиотека компонентов лаборатории ВСЭ

Это каталог элементов, из которых будут собираться макеты электронной лаборатории: кнопок, полей, статусов, диалогов и карточек партий.

**Storybook установлен. Компоненты из макетов пока не перенесены.**

## С чего начать

1. Выберите экран, оформление которого считаете правильным. Например, список ожидаемых поступлений — `arrivals.html`.
2. Попросите Codex собрать используемые на нём варианты кнопок и предложить общий компонент.
3. Проверьте образцы здесь, в Storybook.
4. После согласования подключите тот же компонент к выбранному экрану.
5. Проверьте экран и сохраните результат в Git.

## Что значит «добавить компонент»

Codex выделяет общий код и стили в отдельные файлы. И страница приложения, и Storybook используют одни и те же файлы. Один пример состояния компонента называется story.

Например, у кнопки могут быть основное оформление, вторичное оформление, действие удаления, иконка, недоступное состояние и длинная подпись.

**Копия кнопки только внутри каталога не объединит кнопки на остальных страницах.** Для этого страницы нужно подключить к общему компоненту.

## Задание для первого компонента

> Собери варианты кнопок из arrivals.html. Предложи общий компонент без изменения согласованного оформления. Покажи варианты в Storybook. После согласования подключим тот же компонент к этому экрану.

## Как работать дальше

Выберите элемент в левом меню. Когда появятся компоненты, здесь можно будет просматривать их варианты, а в интерактивных примерах — менять доступные параметры и проверять поведение.

После кнопок добавляйте поля ввода, статусы ВСЭ, диалог удаления и карточку партии. Переносите экраны постепенно.

## Как открыть каталог снова

Попросите Codex: «Запусти Storybook и открой его».

Или выполните в PowerShell:

```powershell
cd C:\journal
npm.cmd run storybook
```

Оставьте терминал открытым и перейдите на `http://localhost:6006`. После перезапуска компьютера каталог нужно запустить снова.

Подробная инструкция находится в файле `STORYBOOK.md` в папке проекта. Правила оформления — в `DESIGN.md`, поведения — в `UX-CONTRACT.md`.
