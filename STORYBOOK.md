# Библиотека компонентов лаборатории ВСЭ

## Что уже настроено

Storybook установлен в этой же папке проекта для HTML и JavaScript. Он открывается в браузере и показывает примеры компонентов. Исходные макеты сохранены без переноса на другую технологию.

Пока каталог содержит вводную страницу. Компоненты из макетов ещё не выделены в общую библиотеку. Установка Storybook сама по себе не меняет и не объединяет кнопки, поля или карточки на существующих страницах.

## Как открыть

Можно попросить Codex: «Запусти Storybook и открой его».

Для самостоятельного запуска откройте PowerShell и выполните:

```powershell
cd C:\journal
npm.cmd run storybook
```

Оставьте это окно открытым. Затем перейдите в браузере на http://localhost:6006. Для остановки нажмите Ctrl+C в окне PowerShell. После перезапуска компьютера Storybook нужно запустить снова.

После скачивания проекта на другой компьютер сначала установите зависимости командой `npm.cmd ci`, затем запустите Storybook.

## Как добавить первые компоненты

1. Выберите один экран, оформление которого считаете правильным. Для начала подходят кнопки на `arrivals.html`.
2. Попросите Codex показать варианты кнопок из этого экрана и предложить состав общего компонента. Выберите основной образец и допустимые отличия.
3. Codex выносит общий код и стили в папку `components/`. Примеры использования хранятся рядом в файлах с окончанием `.stories.js`.
4. Storybook подключает этот общий код и показывает варианты: основная, вторичная, удаление, недоступная, длинная подпись. Один пример называется story — «история» или «состояние».
5. Вы проверяете образцы в браузере. После согласования Codex переводит один экран на использование того же компонента.
6. Проверяем, что экран выглядит и работает правильно, и сохраняем изменение в Git. Затем постепенно подключаем остальные экраны.

Перед добавлением файлов `.stories.js` Codex должен включить их поиск в `.storybook/main.js`: добавить `../components/**/*.stories.@(js|mjs|ts)` в массив `stories`.

Важно: общий компонент должен использоваться одновременно в макетах и Storybook. Копирование разметки только в каталог даёт демонстрацию, но не обеспечивает переиспользование на страницах.

## Готовое задание для следующего шага

> Собери варианты кнопок из arrivals.html. Предложи общий компонент без изменения согласованного оформления. Покажи варианты в Storybook. После согласования подключим тот же компонент к этому экрану. Для него нужны основная и вторичная кнопки, действие удаления, кнопка с иконкой, недоступное состояние и длинная подпись.

После кнопок можно последовательно добавить поля ввода, статусы, диалог удаления и карточку партии.

## Проверки

```powershell
npm.cmd run build-storybook
```

Эта команда проверяет, что каталог собирается. Она не заменяет проверки поведения компонентов и страниц. Дополнение доступности установлено; при появлении компонентов проверки будут доступны в их просмотре.

## GitHub

Репозиторий: https://github.com/AliyaRys/el_vse_lab

GitHub хранит исходники и историю изменений. Отправка файлов в GitHub не публикует каталог Storybook в интернете. Сейчас он запускается локально.

Папки `node_modules`, `storybook-static` и `tmp` не отправляются в Git. `package-lock.json` сохраняется: он фиксирует установленные версии зависимостей.
