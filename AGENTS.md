# Работа с интерфейсом лаборатории ВСЭ

- Перед изменением интерфейса прочитай `DESIGN.md`, `UX-CONTRACT.md` и `STORYBOOK.md`, затем найди существующую реализацию и похожий экран.
- Проект сейчас состоит из HTML-макетов и обычного JavaScript. Не меняй фреймворк в рамках добавления одного компонента.
- Общие компоненты размещай в `components/`; примеры Storybook — рядом в `*.stories.js`. Подключай один и тот же код из страниц и stories. Не копируй реализацию компонента в stories или страницы.
- Первый перенесённый экран — `login.html`. Общие компоненты входа находятся в `components/auth/`, API — `globalThis.VseAuth`; назначение и примеры описаны в `components/auth/README.md`. Остальные экраны ещё не перенесены.
- Для открытия HTML с диска компоненты входа используют обычные скрипты в порядке зависимостей. Storybook импортирует эти же файлы через `story-support.js`. Этот ESM-адаптер не подключается к HTML напрямую. Стили входа принадлежат `components/auth/auth.css`, токены — `components/auth/tokens.css`.
- Для уже выделенного компонента используй существующий API и варианты. Сначала ищи возможность переиспользования или расширения. Не создавай экранную копию с другим оформлением и не придумывай неподдерживаемые параметры.
- Оформление выводи из согласованного образца и существующих правил. Случайные различия старых экранов не превращай автоматически в новые варианты.
- При переносе компонента сохраняй действующие маршруты, поведение, доступные имена, состояния фокуса и русский язык. Данные предметной области не подменяй.
- Добавляй примеры значимых состояний: обычное, недоступное, ошибка, загрузка, длинные данные и узкий экран — где применимо.
- При изменении Storybook запускай `npm.cmd run build-storybook`. При переносе компонента дополнительно проверяй его в браузере и на использующем его экране. Сборка каталога сама по себе не подтверждает поведение приложения.
- Для компонентов входа запускай `npm.cmd run test:ui` после сборки. Проверки находятся в `tests/auth.spec.js`; по умолчанию используется установленный Google Chrome. Новую постоянную библиотечную API-функцию документируй в README компонента.
- `tmp/` содержит локальные рабочие материалы и исключена из Git. Не подключай её файлы как обязательные зависимости приложения или каталога.
